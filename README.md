## Overview

BUG Framework v5.1 is a comprehensive, modular bash-based security testing suite designed for authorized bug bounty and penetration testing engagements. It automates the **full recon-to-exploitation-to-report pipeline** in a single command — OWASP Top 10, IDOR, Broken Access Control, OAuth, SSRF, LFI, CMDi, and more — and **automatically weaponizes confirmed findings** through a built-in self-exploitation chain.

The portable core runs identically on **Kali Linux** (primary) and **macOS** (development), with built-in shims for GNU tooling and bash-5 features.

---

## Features

- **End-to-end automation** — one command: subdomain enumeration → live probing → URL/JS mining → 20+ detection modules → **self-exploitation chain** → deduped Markdown report
- **AUTO-EXPLOITATION (Module 21)** — confirmed primitives are weaponized automatically: LFI→log-poison RCE, SSRF→cloud metadata dump, CMDi→host recon, JWT weak-secret crack + `alg:none` forgery, `.git` repo dump, takeover verification, BAC deep probe
- **Zero-noise results** — 3-layer dedup: in-memory `log_hit` map (no duplicate findings), write-time `uniq_add` (file-level), workspace-wide `sort -u` sweep. Live pre-filter before every fuzz pass — dead targets never get fuzzed
- **Clean JS mining** — noise-filtered endpoint extraction (CDN/static/vendor stripped), API route classification, 10 classes of secret hunting (AWS, GCP, Stripe, GitHub, Slack, JWT, generic)
- **WAF fingerprinting & bypass profiling** — wafw00f + header signatures + block/pass behavior probes + rate-limit threshold + auto-generated bypass payload set
- **API schema discovery** — OpenAPI/Swagger hunting, GraphQL introspection / batching / depth-limit probes, undocumented `v1–v5` version + resource fuzzing
- **Parameter mutation fuzzing** — SSTI (13 payloads), type confusion, hidden-parameter ffuf, JSON/XML mutation (prototype pollution, NoSQLi, mass assignment)
- **OOB support** — blind RCE/SSRF callbacks via `INTERACTSH_DOMAIN`
- **Resume capability** — `--resume`-style checkpointing via `.done` markers (skip finished modules)
- **No broken deps** — every tool call guarded with `command -v`; optional tools degrade gracefully, never crash
- **Cross-platform** — native on Kali; macOS gets GNU grep/base64/timeout/md5 shims, `%N` timestamp fallback, and a defensive `head()` shim (immunized against XAMPP's fake `head`)

## Installation

### Kali Linux

```bash
chmod +x setup.sh bug
./setup.sh        # idempotent — safe to re-run, skips already-installed tools
```

`setup.sh` installs: apt packages (python3, pip, nmap, sqlmap, seclists, jq, git…) · Go 1.22 · 19 Go tools (subfinder, httpx, nuclei, katana, naabu, dnsx, alterx, waybackurls, gf, anew, qsreplace, gau, dalfox, hakrawler, ffuf, getJS, amass, assetfinder, gowitness) · pip tools (waymore, uro, arjun, dirsearch, wafw00f, git-dumper) with PEP 668 `--break-system-packages` · feroxbuster · SecretFinder / LinkFinder / jwt_tool · GF patterns (1ndianl33t + tomnomnom) · nuclei templates · SecLists wordlists.

### macOS (development)

```bash
brew install bash coreutils gnu-grep gnu-time
# bash 3.2 cannot run this script (declare -A) — always use bash 5:
/opt/homebrew/bin/bash bug.sh -d example.com
```

**Requirements:** bash 5+, curl, jq, dig, internet access.

## Quick Start

```bash
# Full scan + auto-exploitation (recommended starting point)
./bug -d example.com

# Scan a list of domains
./bug -l targets.txt

# JS-only deep mode (endpoints + secrets)
./bug -d example.com -js

# Web-only mode (reuse existing workspace, skip recon)
./bug -d example.com -we

# Re-run the exploit chain on an existing workspace
./bug -d example.com -exploit

# Regenerate the report only
./bug -d example.com -report
```

Everything lands in `~/bug-bounty/<domain>/`.

## Scan Modes

### Full Scan Modes

| Command | Description |

| Option | Description |
|---|---|
| `-q` / `--quiet` | Suppress verbose output — findings only |

## ⚔️ Module 21 — Self-Exploitation Chain

Confirmed findings are automatically weaponized — no manual exploitation needed:

| Chain | Primitive | Automatic action |
|---|---|---|
| 1 | CMDi | Drop `/etc/passwd` + `id` + `hostname` + `uname -a` → `exploit/host_recon.txt` |
| 2 | LFI | Read `/etc/passwd`, base64-filter decode, webroot files → `exploit/lfi_reads_dump.txt` |
| 3 | SSRF | AWS / GCP / Aliyun metadata endpoints + internal port sweep → `exploit/ssrf_metadata_dump.txt` |
| 4 | Takeover | CNAME → NXDOMAIN verification of takeover candidates |
| 5 | `.git` | Full repository dump via git-dumper |
| 6 | JWT | Weak-secret crack (HS256/384/512) + `alg:none` admin forgery |
| 7 | BAC | Deep-probe sensitive endpoints for PII / data exfiltration |

Every chain writes evidence files to `exploit/` and reports a summary at the end of the scan.

## After the Scan — Recommended Workflow

1. **Read the summary** — the scan ends with top findings per module (`log_hit` lines)
2. **Open the report** — `less ~/bug-bounty/<domain>/report/bug_report.md`
3. **Triage critical/high Nuclei findings** — `vulns/nuclei/nuclei_critical_high.txt` — highest accuracy, start here
4. **Check the exploit chain output** — `exploit/` contains dumped RCE output, cloud metadata, JWT forgeries, takeover proof
5. **Verify secrets in JS** — any valid key in `js/secrets_found.txt` = instant critical report
6. **IDOR with two accounts** — re-test `vulns/idor/idor_seq_diff.txt` URLs manually, swapping sessions
7. **Validate XSS** — open dalfox results in a browser to confirm
8. **SSRF OOB** — if you set `INTERACTSH_DOMAIN`, check `vulns/ssrf/oob_payloads_sent.txt` against your collaborator
9. **Import to Burp** — load `endpoints/all_endpoints.txt` + `params/all_params.txt` into Param Miner for deeper manual testing
10. **Write up** — confirmed findings with evidence from the dumps + report

## Roadmap & Known Limitations

- **Standalone module flags** (`-sub`, `-xss`, `-sqli`, `-ssrf`, `--quick`, `--deep`, `--cookie`, `--proxy`, `--threads`, `--rate`…) are defined in the help/parser but not yet wired into the main dispatcher — all detection modules run as part of the full scan
- **`-one`** currently behaves as a full scan; a true single-host pipeline (skip subdomain enum) is planned
- **Exploit chains 5–7** (`.git` dump, JWT, BAC deep probe) are implemented in Module 21 and activate once `mod_bac`, `mod_jwt`, and `.git` detection modules are added (currently guarded no-ops)
- **Classifier & screenshots** (v5.0-era modules) are not in the v5.1 pipeline — their workspace dirs are reserved
- **Report** is Markdown; HTML dashboard is planned
- **HTTP request smuggling** is handled by a separate dedicated tool (not part of this suite)
